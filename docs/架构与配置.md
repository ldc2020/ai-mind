# 架构与配置说明

## 本次重构的边界

保留 FastAPI、JSON 文件格式、原生前端和现有第三方库。没有引入新的 UI 框架，也没有制作桌面版。主入口 `static/js/app.js` 只负责加载默认模板、恢复文档和启动自动保存。

前端采用按职责拆分的传统脚本，仍共享编辑器状态；本次没有把所有历史功能改成彼此隔离的 ES Modules。加载顺序记录在 `static/js/modules.json`，HTML 使用相同顺序，`npm run check` 自动检查两者一致性。新增模块需要同时更新两处。

共享状态主要在 `core/` 中，功能内部的计时器和编辑状态仍放在对应模块中。`engine/compatibility.js` 集中管理关联线渲染补丁；摘要、浮动节点仍需读取库内部结构，升级引擎时也要检查这两类功能。不要直接修改 `vendor/` 中的压缩库。

## 后端配置

优先级：环境变量 > `config/local.json` > `config/defaults.json`。
配置在启动时加载，修改后重启服务。JSON 不支持注释，所以字段说明统一放在此表；加载和校验逻辑位于 `config/settings.py`，带中文注释。

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| app_name | AI Mind | 服务名称及就绪接口中的应用标识 |
| version | 1.2.0 | API 文档及页面右下角显示的版本 |
| host | 127.0.0.1 | 服务监听地址 |
| port | 8001 | 服务端口，1～65535 |
| reload | true | 开发热重载；常驻运行建议 false |
| data_dir | data | 文档和 `_tree.json` 的存储目录 |
| static_dir | static | 静态页面及资源目录 |
| log_dir | logs | 历史托盘启动器的日志目录 |
| log_level | info | 网页服务日志级别 |
| startup_timeout_seconds | 15 | 历史启动器等待服务就绪的最长秒数 |

环境变量统一使用 `AI_MIND_` 前缀，例如：

```powershell
$env:AI_MIND_PORT = "8100"
$env:AI_MIND_RELOAD = "false"
python main.py
```

相对路径相对于项目根目录，而不是当前命令行目录。修改数据目录不会自动搬迁旧文件；若要迁移，先停止服务并备份原目录，再复制全部文档和 `_tree.json`。

Windows EXE 的内置资源与可写数据分开：页面/默认配置随 EXE 打包；放在项目 `dist` 内运行时沿用项目数据，单独运行时默认使用 `%LOCALAPPDATA%\AI Mind`。`AI_MIND_HOME` 可以覆盖可写配置/数据的基准目录；用户 `config/local.json` 相对于此目录读取。数据不会保存到 PyInstaller 的临时解压目录。新版不再混合导入项目磁盘上的 Python 源码。

构建同时发布 `dist/AI Mind.exe` 和 `dist/launcher.exe`，二者内容相同，兼容已有快捷方式。Windows 验收会检查两个入口的 SHA256 一致，防止遗留旧启动器。重新构建前先退出运行中的程序，避免覆盖被锁定的 EXE。

## 前端配置

`static/js/config/app-config.js` 对每组设置有中文注释，修改后刷新页面：

- `api.basePath`：同源 API 前缀，默认 `/api`；若修改，需要同步服务端路由。端口直接随当前站点，无须再写一次。
- `behavior`：自动保存周期、消息时长、备注隐藏延迟、富文本工具栏增强时机。时间单位均为毫秒。
- `ai`：默认服务地址、模型和 temperature。用户已经保存的设置优先，默认模型名称保持兼容旧项目，不代表推荐所有服务均支持它。
- `editor`：新文档默认布局、主题、标签数、缩放范围和引擎开关。已有文档的布局、主题优先。
- `floatingNode`：自由节点/依附节点默认文字、颜色、坐标、字号、间距及标签数。已有节点保存的样式优先；坐标和边框宽度 0 会保留。
- `tooltip`：备注浮层距节点的间隙、屏幕边缘留白和最大高度。
- `colors`：自定义导图控件的默认强调色。
- `export.filename`：导出文件默认名称，不含扩展名。
- `storageKeys`：历史浏览器存储键名；通常不修改，修改后旧偏好不会自动迁移。

配色/图标目录在 `config/catalogs.js`；页面的 CSS 设计变量在 `static/css/tokens.css`。修改工具栏支持的布局还需要同步 `index.html` 中的按钮。`config/prompts.js` 专门保存 AI 系统提示词。

### 导图风格

选择器提供六种整体风格，包含两种彩色分支主题：

| 配置键 | 显示名称 | 连线与节点样式 |
| --- | --- | --- |
| rainbow | 彩虹弧线（默认） | 多色贝塞尔曲线、主节点实色、子节点同色系浅底 |
| colorfulBubble | 缤纷气泡 | 多色平滑曲线、胶囊形节点、同色系细边框 |
| organic | 灵动弧线 | 舒展贝塞尔曲线、线条分支、较宽松的分支间距 |
| bubble | 柔和气泡 | 平滑曲线、胶囊圆角、带底色与细边框的节点 |
| minimal | 极简曲线 | 细曲线、无底色的轻量文字节点、更充足的留白 |
| cards | 圆角卡片 | 大圆角折线、分层卡片、明确边框与内边距 |

以上参数集中在 `static/js/config/catalogs.js` 的 `THEME_CONFIGS` 中，并有中文注释。
`BRANCH_PALETTE` 按主分支顺序循环分配色系，支持增删颜色项：`line` 控制连线与主节点底色，`surface` 控制子节点浅底色，`text` 控制子节点文字。`branchMainTextColor` 控制主节点文字，`branchNodeFill` 控制子节点是否显示浅底。将主题的 `branchPalette` 设为空数组可关闭多色分支。

彩色连线使用引擎内置 RainbowLines 插件，节点配色通过 `engine/compatibility.js` 的样式读取兼容层补充。颜色只在渲染时计算，不写入节点数据，不覆盖用户的手动样式。新增节点按当前所属分支取色；分支顺序调整后会重新分配色系。自由节点及独立关联线仍使用各自设置。升级第三方库时应运行完整浏览器回归检查此兼容层。

源码运行时修改配置后刷新即可；Windows EXE 内置前端配置，修改源码配置后需要重新执行 `python scripts/build_windows.py` 打包。
`lineStyle: 'curve'` 控制弧线；`lineStyle: 'straight'` 配合 `lineRadius` 控制圆角折线。
当前库的曲线主要适用于逻辑结构、思维导图和垂直时间轴；鱼骨图等其他布局使用自己的连线规则。
切换风格不改变文档的布局类型，节点已有的手动样式仍优先于主题默认样式。

旧文件的主题键通过 `LEGACY_THEME_ALIASES` 映射：default/经典/绿色/暖阳映射到灵动弧线，粉紫等映射到柔和气泡，暗色/极简映射到极简曲线，蓝色/明亮/雪白映射到圆角卡片。旧配色不再保留为单独选项。加载不批量改写文件，下一次保存会记录新风格键。

不会把算法中的 0/1、SVG 标准命名空间、JSON 字段名、图标路径和格式协议当作用户设置。局部控件的精细 CSS 仍在对应样式或渲染代码中；全局外观修改优先从 tokens 和主题配置入手。

## 数据与保存

唯一磁盘读写入口是 `backend/repository.py`。导图数据不做白名单截断，保留 `_floatingNodes`、`_relations`、摘要及未来扩展字段。保存先写同目录临时文件，再原子替换目标，避免中途失败损坏原文件。

`features/files/documents.js` 统一手动/自动保存。保存失败保留未保存状态，切换文档时若保存未成功则取消切换。保存请求期间又发生编辑时，新修改仍保持未保存状态。导入后的首个保存会创建包含导入内容的新文件。

原子替换保障单次文件写入完整性，不等于多个客户端对同一文档的协同合并。本项目仍是本地文件型应用，不提供多人实时协作。

## 依赖与测试

- Python 网页依赖：`requirements.txt`；测试依赖：`requirements-dev.txt`。
- 可选历史托盘依赖：`requirements-launcher.txt`，不影响网页安装。
- Puppeteer 作为开发依赖固定在 `package.json` 和 `package-lock.json`；锁文件需要提交。
- 业务运行库保留为本地文件，`static/vendor/manifest.json` 记录内容哈希，检查命令会验证。没有在此次重构中升级这些库。
- `python scripts/test.py` 创建临时数据目录，运行接口测试、脚本语法/加载顺序/库哈希检查，以及无界面 Chrome 回归。测试结束后关闭自己启动的服务和浏览器。
- 不运行 `tests/legacy` 中的旧脚本，它们可能修改默认实例中的数据。

浏览器测试中的 HTTP 500 是故意模拟的保存失败，用于确认数据不会被误标为已保存。真实 AI 服务不在回归中调用，避免产生费用；设置与请求格式通过模拟响应测试。
